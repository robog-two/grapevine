# Personal CRM — Product Spec (v2)

*A relationship-management tool for individuals: a Rolodex, a filing cabinet, and a database, expressed as two synced views over one data model.*

---

## Core Concept

One person → one canonical record, viewable as:
- A **manila folder** in a **filing cabinet** (spatial, freeform canvas)
- A **row** in a **spreadsheet/database** (tabular, filterable, graph-aware)

Both views read/write the same underlying SQL data. Always-online cloud app, encrypted at rest, transparent to the logged-in user via WebCrypto-managed keys.

---

## Pages & Features

### 1. Filing Cabinets
Top-level containers (e.g. "Startup," "College Professors"). **Many-to-many**: a person can belong to multiple cabinets at once. A cabinet is a lens/filter over the person table, not an exclusive home.

### 2. Cabinet View (folder browser)
Infinitely-scrollable vertical canvas of manila folders for people in that cabinet (or "All People"). Folders have real x/y positions — draggable, groupable, visually arrangeable, not just list order.

### 3. Person Folder (individual record)
A canvas of items belonging to one person: Contact Card, notes, photos, files, .eml imports, calendar/reminder items, @mention links. All items are timestamped and positioned like folders are.

### 4. Contact Card (Rolodex card)
Core fields: name, reach-me-at info, how discovered, plus custom fields. Populates the Spreadsheet View as columns.

### 5. Spreadsheet/Database View
Tabular view across all people (or filtered by cabinet), with contact-card and custom fields as sortable/filterable columns. Also the home of the **relationship graph** (see #7) — a graph/network sub-view showing @mention-derived links between people.

### 6. Reminders & Calendar
A reminder is just another item type in a person's folder — added the same way as a photo or text snippet. Composing one:
- Pick date + a default time-of-day (Morning / Afternoon / Evening)
- Optional note ("follow up about the Series A intro")
Reminders sync one-way to the user's calendar via **iCal feed** (subscribe once, all future reminders appear automatically). No in-app push notifications required — the calendar app is the notification surface. A dedicated **Calendar View** page shows all upcoming reminders across every person/cabinet in one place.

### 7. @Mention Linking & Relationship Graph
Typing `@Name` inside any rich-text note auto-links to that person's folder — same mechanic as any other attachment, no separate "add relationship" UI. Every @mention is stored as a directed edge (mentioning person → mentioned person, with the sentence/context as the edge label). The **Database View** exposes this as a graph visualization: click a person to see everyone they're connected to and how.

### 8. Attachments & Content Items
Item types: rich text snippets, photos, generic files, **manually-imported .eml files** (parsed and rendered with sender/subject/date/body, not shown as a raw blob), reminders (#6), @mention links (#7). All positioned on the same canvas, all timestamped.

### 9. Timeline / History ("Rewind")
Every edit is logged as a **linear, append-only timeline** per folder — like a Wayback Machine for a person's record. Users can scrub backward through a folder's history and view any past state. Old versions of items can be **downloaded or copied** back into the live folder if the user wants to restore something — but there is **no one-click revert/rollback**; restoring is always an explicit new action, keeping history strictly linear and non-destructive.

### 10. Trash
Soft-delete only. Deleted items retain full metadata (original folder, added/updated dates, deleted-on date) and are recoverable from Trash. Complements the Timeline — Trash is for explicit deletions, Timeline is for edits.

### 11. Custom Fields Engine
Field types: **text, date, dropdown/select, checkbox, link (URL), currency**. Defined per-field, appear on the Contact Card, and aggregate as typed, sortable/filterable columns in the Spreadsheet View (e.g. currency sorts numerically, dates sort chronologically).

### 12. Global Search
Full-text search across everything: names, custom fields, rich-text notes, and the parsed contents of attached .eml files and files (where text-extractable). One search bar, results grouped by person.

### 13. Import / Export
- **Import**: vCard and CSV (bulk-create people + map columns to fields).
- **Export**: vCard and CSV, for backup/portability.
- **Duplicate detection**: on import (and periodically), flag likely-duplicate people (name/email/phone fuzzy match) and surface a merge suggestion. Merging combines fields, attachments, and timeline history from both records into one.

### 14. Sharing
No real-time collaboration — this stays single-editor. But individual folders (or read-only cabinet views) can generate a **shareable link** for sending someone a clean, read-only snapshot of a record (e.g. sending a contact's info to a friend).

### 15. Infinite Canvas / Spatial Layout Engine
Shared mechanic behind Cabinet View and Person Folder View: freeform x/y positioning, manual grouping, vertical infinite scroll. Positions persist per view.

### 16. Responsive Layout (Desktop ↔ Mobile)
Desktop: wide 2D canvas. Mobile: same items, same infinite scroll, collapsed to a single-lane vertical strip (positions collapse to a consistent top-to-bottom order rather than 2D placement).

### 17. Security & Architecture
Always-online cloud app. **Encryption at rest**, with keys managed client-side via WebCrypto so decryption is transparent once the user is logged in (no extra passcode friction post-login).

## Data Model (draft)

- `people` — core identity
- `cabinets`, `people_cabinets` (many-to-many join)
- `contact_cards` — 1:1 with people, core Rolodex fields
- `custom_fields` (definitions: name, type), `custom_field_values` (per person)
- `items` — polymorphic table for notes/photos/files/.eml/reminders, with `type`, `position_x`, `position_y`, `created_at`, `updated_at`, `folder_id`
- `mentions` — edges: `source_person_id`, `target_person_id`, `context_snippet`, `source_item_id`
- `reminders` — extends `items`: `date`, `time_of_day` (morning/afternoon/evening), `note`, iCal feed reference
- `timeline_events` — append-only log: `item_id`, `change_type`, `snapshot`, `timestamp`
- `trash` — soft-deleted items with original location metadata
- `share_links` — token, scope (person/cabinet), read-only
- Encryption: per-user data key wrapped by a key derived client-side (WebCrypto), never sent to the server in plaintext

## Suggested build order
1. Data model + Contact Card + Cabinet/Folder canvas (core loop)
2. Spreadsheet View (same data, second lens)
3. Attachments (notes/photos/files) + Trash
4. Timeline/Rewind
5. @mentions + relationship graph
6. Reminders + iCal sync + Calendar View
7. Custom field types + Global search
8. Import/export + duplicate detection/merge
9. Sharing links
10. Encryption at rest
